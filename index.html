Option A

Sticky Bundle Tray

Shoppers add kits straight from the grid into a sticky tray at the bottom of the page. The tray shows the kit slots, a live 2 → 3 → 4+ savings progress bar, the add-ons at 25% off, and one "Add bundle to cart" button. The "mix" in Mix & Match happens where the shopper can see every kit at once.

How it works

  1. Each eligible kit shows Add to bundle. Bundles that aren't part of the offer keep Quick Add.
  2. The tray fills its slots and moves the progress bar. Prices update with the same rounding as the Discount Function.
  3. Shoppers can add extras from the tray, then add everything to the cart in one request.

Assessment

Pros

  • It's the clearest way to show "mix & match": shoppers see different kits side by side and watch the discount grow.
  • The progress bar always shows the next goal ("Add 1 more kit to save 15%").
  • One button adds the whole bundle, so the grid never opens a modal.
  • Likely to lift AOV the most, because shoppers keep scrolling and adding.

Cons / risks

  • Kits with variants (e.g. colourways) need a small inline variant picker before they can go in a slot.
  • The tray takes about 90px of desktop height and needs careful handling next to the existing sticky ATC and chat widgets.
  • This is a new UI pattern, so the BYOB box markup can't be reused as-is.

Option B

Builder Sidebar (PDP box on the PLP)

The PDP's "Buy more, save more" box moves onto the PLP as a sticky right-hand rail. Shoppers choose the bundle size first (2 / 3 / 4+), then fill the empty slots by picking kits from a 2-column grid. It reuses the V3 "pick how many, then choose which" flow, so the PLP and the PDP behave the same way.

How it works

  1. Shoppers choose a bundle size in the rail. The rows match the PDP: 2 kits · 3 kits · 4+ kits.
  2. Shoppers tap Add to bundle on a card to fill the next empty slot. Each card shows its price inside the bundle.
  3. Shoppers add extras in the rail, then press Add to cart. The button stays disabled until every slot is filled.

Assessment

Pros

  • It matches the PDP box shoppers already know, which keeps the whole site consistent.
  • The highest reuse: the rows, slots, swap and extras markup and CSS come from mix-match-offer-v3.
  • Committing to a size up front ("I'm buying 3") gives a clear goal.

Cons / risks

  • The grid drops to 2 columns on desktop, so fewer products show above the fold. This is a big change to the new PLP design.
  • Asking for a size first adds friction for shoppers who only want 1 kit.
  • On mobile it needs a sticky strip plus a sheet, which makes the screen busier.
  • The new Buy More Save More banner is replaced or demoted.

Option C

Smart Quick Add + live banner

The new PLP layout stays exactly as designed. There are two upgrades: the Buy More Save More banner becomes cart-aware and live, and Quick Add on eligible kits opens a side drawer that contains the BYOB box (tiers, cart notice, extras). This is the lightest touch and the fastest to ship.

How it works

  1. The banner reads the cart: "1 kit in your cart, so add 1 more to save 10%". Unlocked tiers light up.
  2. Each eligible card shows its next-tier price ("$54.00 each with 2+ kits").
  3. Quick Add opens a drawer with the PDP box for that kit, as in your 2nd screenshot. Adding updates the banner and shows a toast.

Assessment

Pros

  • The new PLP design (header, banner, grid, chips) stays as it is.
  • The drawer reuses the PDP box (mix-match-offer-v3), so customers learn one component.
  • The least new JavaScript and the lowest QA risk. It can ship fast and be A/B tested.
  • The banner becomes a useful, accurate nudge instead of static copy.

Cons / risks

  • Mixing still happens one kit at a time (add → close → add another), so it's less visible as a "build".
  • A smaller AOV lift than A is likely.
  • The Quick Add modal fetch has to return the BYOB block, so it needs a dedicated product view (?view=byob-quick).

Decision

Compare the three options

All three use the same Discount Function and the pottery group in custom.mix_match_groups. The PLP only shows the price, and checkout stays the source of truth. The options differ in where the "building" happens.

My recommendation: Option A (with C's live banner)

The PLP is the only page where a shopper sees several kits at once, which is where "mix & match" makes the most sense. The tray turns the offer into something shoppers can see and track progress on, without breaking the new grid design. The cart-aware banner from Option C is cheap and helps every option, so I'd include it either way. If time is tight, ship C first as phase 1 and add the tray in phase 2. C's banner and card price line are the groundwork A needs anyway.

Things every option must handle
Tier copy mismatchThe PLP banner says "2 kits up to 15% · 3 kits up to 20% · 4 kits up to 25%", but the BYOB offer is 10% / 15% / 20% (+25% on add-ons at 2+ kits). The banner should read its tiers from the custom.mix_match_groups shop metafield so it can't drift.
Bundles are excludedPottery Date Night and Ultimate Pottery Bundle don't have mixMatchGroup, so they don't count as kits. Their cards need a clear state ("Not part of Build Your Own Bundle") and keep a normal Quick Add.
Which collection?If most items in Pottery Kits are excluded bundles, there's little to mix there. The builder works best on the top-selling / all-kits collection (pottery, candle, kids, PBN, texture and wall art). We need to confirm the eligible product list.
Cart awarenessCount kits already in the cart via /cart.js, the same way the PDP shows "3 kits already in your cart, so 20% is unlocked", and start the progress from there.
VariantsKits with colourways need a variant pick before they're added (an inline select on the card or in the slot). Sold-out variants are hidden, which respects quick_add_hide_sold_variants.
Add-onsAdd-ons come from the same add-ons collection and carry the _mix_match_addon: pottery line property. They show 25% off only at 2+ kits.
One cart requestKits and add-ons go into a single /cart/add.js call with items[], then the theme's cart drawer and count refresh.
Price display rulesPer-unit rounding is half-up to the cent, the same as the PDP and the Function. Sale prices stack, so the discount comes off the current price, not the compare-at.
